# Canada Place local building-cut broadphase

2026-11-16. This is a startup optimization of existing registered support geometry. No building footprint, road datum, apron boundary, collision rule, material or rendered surface is redesigned.

## Observed bottleneck and change

A complete Node `loadCity`/`CollisionWorld` profile loaded36,418 buildings,30,063 roads, the eastern extension, merged building metadata,45,600 City trees, terrain binary and seawall. The two Canada Place site factories took18.856 seconds together. Their primary road area, connectors, Fairmont apron and PwC apron issued nine small local polygon differences, each receiving all36,418 city building footprints (except the existing explicit PIER exclusion on connectors). Polygon parsing, sweep work and garbage collection dominated.

`buildingsOverlappingPolygon` performs a conservative axis-aligned envelope test before converting selected footprints to polygon-clipping inputs. Every intersecting or touching envelope is retained in source order and as the same source object. It handles enclosing footprints and crossing edges without relying on a building vertex falling inside the subject. A1µm guard retains near-contact coordinates through boolean rounding. Invalid bounds fail open. There is no mutable-source cache.

The same original polygon difference still decides actual intersections and concavity. The coarse PIER exclusion and explicit existing-deck connector cut remain unchanged. The nine building-cut inputs reduce to13,0,3,2,13,0,4,3,2 buildings respectively, with explicit deck cuts retained. Only provably disjoint building envelopes are rejected; no road/terrain edits or altered support allowances are involved. The three callers are `canada-place-site.ts`, `fairmont-apron-site.ts` and `pwc-apron-site.ts`.

## Exact equivalence evidence

Before implementation, an instrumented copy of the unchanged full actual constructor recorded every original global building subtraction. `tests/fixtures/canada-local-cuts-unfiltered.json` stores those nine subjects, extra cuts, source exclusions and exact outputs, plus final Canada/Fairmont/PwC support polygons and39 boundary samples. Its provenance is the unfiltered69b3179 implementation; it was not generated by the optimized algorithm.

The test loads complete current real data through the same conversion/layer sequence, replays the filtered cuts, and requires deep equality of coordinates, order, winding and holes with all nine unfiltered outputs. It then invokes the real installed constructor and requires exact final support polygons, exact contains decisions and exact support heights at all39 recorded boundary samples. It also checks that no full-city boolean input survives. Synthetic cases cover enclosing buildings, crossing edges with no vertex inside, exact edge/corner contacts, near-rounding gaps, concave envelope false positives, source object/order preservation and later source-footprint changes.

Existing Canada Place/Fairmont/PwC geometry and contact tests remain part of the focused validation. This optimization adds no new rendering and cannot legitimately be accepted by a visual approximation if polygon equality fails.
