# Debug Canada North planar water reflection

## Reason for replacing the cube trial

The prior static cube trial is retained in `water-scene-reflections.ts` and its tests as a rejected experiment. Native `artifacts/local/water-scene-on-native.png` and `water-scene-combined-native.png` showed a dark local reflection patch ending at the 260 m water-fragment fade into pale distant water. Its fixed position also cannot reproduce nearby ship/shore parallax. Native preparation was approximately 1,198 ms CPU wall time for six scene faces plus PMREM; it was not accepted as default.

This candidate instead renders **the current gameplay camera reflected across the actual ocean plane, world y=0.065**, into one 512 × 512 target. It uses the installed Three r182 `examples/jsm/objects/Reflector.js` reflected-camera, projective texture matrix and Lengyel oblique clipping implementation. Three remains under its existing MIT licence. The Reflector is detached, invisible, and never added to the game scene; only its `onBeforeRender` callback is invoked. There is no extra world mesh, ocean displacement or contact change.

The target is sampled from world position. Reflector's texture matrix includes its plane model matrix for local vertex inputs; this candidate multiplies by the inverse plane model matrix before consuming `vWorld`. The reflected camera reverses horizontal handedness, already represented by this matrix; no additional texture flip is applied. Oblique near-plane clipping removes scene geometry below the water. The far plane is at least 15 km (the current gameplay camera already uses 24 km), preserving the existing photo horizon in the reflected frustum without changing the player's camera. All current static chunk visibility is preserved; there is no global culling extension.

## Bounded control and optics

The existing debug checkbox is now labelled **Planar north-harbour reflection (day only)**. `setDebugWaterScene` remains the control API, while `updateDebugWaterScene` now receives the actual PerspectiveCamera rather than only its position. The ordinary default remains off. Camera eligibility is full within 90 m of `[686.698,-697.34]`, fades smoothly to zero at 170 m, and is off below the ocean surface or outside daytime. There is **no circular per-water-fragment distance fade**. Only the shared water fragments at world y=0.065 (1 mm float tolerance) use the target; other lake/pond heights retain the prior water. Points outside the captured projection or behind the reflected camera fall back to the original shader.

Capture uses linear half-float radiance with no extra tone mapping, tint, environment rotation or intensity multiplier. The target replaces the complete previous sky/reflection plus analytic sun alternative once, before the existing additive water noise, water fog, tone mapping and colour-space output. Thus captured sky/scene illumination is not supplemented by a second analytic solar lobe. Existing scene sky, lights, HDR orientation, materials, weather and panorama are unchanged. Source assets remain their existing licensed images; no new photographs or downloads are introduced.

This first registration trial is deliberately a **mean-plane reflection**: projected texture coordinates are not perturbed by the wave normal. Existing normal-driven Fresnel still varies, but the reflected image can look mirror-stable. It is not claimed as finished harbour optics. A normal-driven projective perturbation would need a separate reviewed comparison after registration. The source panorama is still display-referred photography on its existing approximate plane, not calibrated distant geometry/radiance. Existing water fog remains, including its effect on an already atmosphere-rendered scene capture; haze/contrast is therefore not claimed physically calibrated.

## Updates, restoration and resource cost

The initial capture yields one frame and waits for the existing photo material's image readiness. The capture is deferred when an ordinary architectural reflection updated that frame or the existing quality/intro gate forbids work. It refreshes after weather/orientation invalidation, camera translation above 4 cm, rotation above 0.001 rad, or projection changes. Otherwise it reuses the result. Explicit lighting/weather/orientation invalidation keeps reflection weight zero across deferred frames until a fresh capture succeeds; ordinary small camera motion retains the valid cached result. **Movement can require a scene render every frame**; there is no claimed frame-rate saving and no invented FPS measurement. A failed capture unbinds its partial result and does not repeatedly retry until explicit invalidation or re-enable.

All meshes using the shared water material are hidden during capture. Scene children outside the static World root (except lights/the sun target) are hidden and restored. This includes dynamic actors **and** separately attached DetailedTrees/ForestDetail objects: only the root fallback foliage remains where currently visible. It is not a capture of every static detail object in the scene. Ordinary architectural captures also hide the water while this option is enabled, avoiding feedback through glass probes. World geometry visibility is not widened or reclassified. Both `shadowMap.autoUpdate` and `shadowMap.needsUpdate` are temporarily false, preserving the current static shadow map and avoiding an unaccounted shadow redraw. Prior flags are restored so the normal gameplay render can refresh its shadows.

An outer `try/finally` wraps Three's callback because Reflector itself does not recover from renderer exceptions. It restores target/cube face/mip, logical and actual viewport/scissor, scissor test, depth-write mask, XR, auto-clear flags, tone mapping, shadow update flags, the detached reflector visibility/force flag, water and actor visibility. Material teardown clears target uniforms before disposing the owned target, reflector material and tiny detached plane geometry. HDR/wave layers remain independently removable in all enable/disable orders.

Resource allocation: 512² RGBA16F colour is **2,097,152 bytes (2 MiB)**, without mipmaps. The default depth attachment is DEPTH_COMPONENT24, about **0.75–1 MiB** depending driver storage; diagnostics budget 1 MiB. MSAA is zero. There is no cube, PMREM, HDR copy or new scene asset. These estimates exclude driver overhead, shader compilation and renderer-owned auxiliary resources.

`lighting.waterScene` reports backend, capture count, last/total preparation CPU wall time, last/total capture draw calls and triangles, camera weight, target dimensions and colour/depth byte estimates. Capture counters are recorded separately before the main render resets `renderer.info`; accumulation mode is also handled. Failed allocation before render reports zero capture draws instead of copying prior main-frame counts. These are submission counts and CPU wall durations, **not GPU timing**.

## Validation and native acceptance

Focused tests exercise the installed Reflector callback with a controlled renderer: actual mirrored camera pose, preserved gameplay projection, near-plane above/below classification, world-to-texture coordinates, current static visibility, failure cleanup, photo readiness, camera/invalidation updates, idle reuse, resource disposal, capture accounting, and all 36 HDR/wave/planar toggle orders. They do not render GPU pixels or establish visual quality.

Root should compare at the same reached Canada NorthPoint camera as the failed cube, first planar alone, then the existing HDR/wave options if useful. Inspect horizon/structure registration and absence of the 260 m patch edge, then walk/rotate the ordinary camera and record capture calls, triangles and wall duration separately from the main frame. Default promotion requires both the image and motion/cost review; this checkpoint remains diagnostic only.
